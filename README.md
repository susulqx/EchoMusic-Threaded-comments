# 评论区树状显示

EchoMusic 插件。把歌曲 / 专辑 / 歌单评论里的楼层回复，按回复关系缩进成树展示，支持引导线与分支折叠。

## 功能

- **三档显示模式**
  - 线条模式 · 不收起主评论：折叠时保留父评论正文，只隐藏它下面的回复。
  - 线条模式 · 收起主评论：折叠时连父评论正文一起收起，只留作者行与 `+N` 恢复按钮。
  - 仅缩进：只缩进，不画引导线、不放折叠节点。
- **引导线**：主干竖线从父头像圆心垂下，每一个子回复用 12 px 圆角弧拐到自己的头像左缘。主评论到每一条一级回复之间也有一条同样的根分支，同层的一级回复因此串成一条线，而不是各画各的。
- **分支折叠**：竖线上骑着一个 `−` / `+` 圆节点（6 px 实心 + 12 px 命中圈），点击收起或展开整棵子树；键盘可 Tab 聚焦、Enter / 空格触发，`aria-expanded` 随状态更新。
- **固定高度回复容器**：把楼层限制在 240–960 px（默认 480）内滚动，回复较少时自动收缩。
- **楼层内分页**：回复很多时按「每页 20 个根回复」分页，子回复跟随所属根同页，不会割断分支；在末页点「加载更多」会把请求交回宿主。
- **隐藏引用**：默认收起回复正文下方那段「被回复评论」的引用块 —— 树状缩进后父评论就在正上方，再复述一遍只是重复。可在设置里关掉。
- **新加载提醒**：点「加载更多」后，这次新来的**二级及以下**回复在名字那一行的有效内容右侧标一个红点；这次新来的**一级**回复在与旧回复的分界处画一条带 `NEW` 字样的灰色横线。两个提醒分别可关，分界线粗细可在设置里调（1–6 px，默认 3）。为什么要标：重排会把新加载的子回复插到它所属的旧父评论下面，位置跟着变了，肉眼分不出哪些是这次新来的。

## 设置

安装后在「设置 → 插件 → 评论区树状显示」中调整：

| 选项 | 说明 |
| --- | --- |
| 评论区树状显示 | 总开关，关闭后立即恢复宿主原有平铺样式。 |
| 固定高度回复容器 | 依赖总开关。 |
| 容器最大高度 | 依赖总开关与容器，240–960 px，步进 20。 |
| 显示模式 | 依赖总开关，三档见上。 |
| 隐藏回复下方的引用 | 依赖总开关，默认开启。只写容器标记由 CSS 隐藏，不改动宿主节点。 |
| 新加载的子回复显示红点 | 依赖总开关，默认开启。 |
| 新加载的回复前加分界线 | 依赖总开关，默认开启。 |
| 分界线粗细 | 依赖总开关与分界线，1–6 px，步进 1，默认 3。 |
| 楼层内分页 | 依赖总开关，默认关闭。 |

设置保存在插件私有存储键 `threaded-comments:settings`，调整后立刻对所有已展开的楼层生效，无需重新展开。

## 实现说明

- 回复的父子关系来自插件对 `/comment/*` 响应的旁路观察（manifest 声明 `serverIntercept`），不改写请求与响应。
- 宿主把回复按接口返回顺序平铺（A B C D），树序要求子回复紧跟父评论（A D B C）。**排序真的移动 DOM 节点**（`src/order.js`），而不是只改视觉顺序：跨条拖选与复制走的是 DOM 顺序，视觉与 DOM 不一致时会复制出乱序文本。宿主是 `:key` 的 keyed list，只保证复用不保证顺序，它下次 patch 把顺序拨回自己的口径时，容器的 MutationObserver 会再拨一次；停用或关闭时按「首次见到的顺序」插回原位。
- 楼层回复与其接口数据的对齐键是「昵称 + 时间」；对齐失败时该条保持原有相对位置排在末尾，不会错挂到别的分支下。
- 缩进由 `padding-inline-start` 完成，引导线由插件自建的 SVG 图层绘制；除回复节点的先后次序外不移动、不改写宿主节点的内容。
- 根分支连接的是楼层容器**外面**的主评论头像（容器的祖先 `.comment-item > .comment-avatar`），所以图层会向上、向左扩出容器，用负坐标的 `viewBox` 画到容器之外；根分支只画线、不放折叠节点，整层收起仍由宿主的「收起回复」按钮负责。
- 隐藏引用同样只用容器上的 `data-echo-quote-off` 标记 + 一条 CSS 规则（`.comment-floor-quote { display: none }`），不删除也不改写宿主的引用节点，关掉开关或停用插件即完全复原。
- 新加载提醒靠每层一份「见过的对齐键集合」：容器第一次出现时看到的全部算既有，之后每轮重算只比较出一个新增批次并记住它，所以宿主的任意一次 patch（改文案、折叠、翻页）都不会让红点自己消失。红点只写在「二级及以下」的回复上，一级回复交给分界线；分界线只画在新旧交界的第一条一级回复的上边框，用边框而不是伪元素，不占高度也不会把引导线的锚点挤歪。
- 红点的横向坐标由 `src/mark.js` 现量：名字行是 flex-wrap，里面还有 VIP 徽章、「回复某某」这些宽度随数据变化的节点，纯 CSS 只能贴到整条回复的右边缘，离内容常常隔着大半个屏。所以量出「与第一个可见子节点同一行」的那些节点的最右边界，写进回复的 `--echo-tree-dot-x / -y`，红点本体仍是 `::after`。坐标在每次重算后重写，标记撤除时一并清掉。
- 分界线粗细写在容器变量 `--echo-tree-divider-width` 上（`src/container.js` 的 `applyContainerAttrs`），规则只管读；`NEW` 字样是这条边上的 `::before`，`translate(-50%, -50%)` 压在线的正中，底色取主面板色把线盖住。
- 折叠状态按「昵称 + 时间」记录而非索引，宿主追加新回复后原有折叠不会错位。
- 关系缓存有上限，且正在展示的楼层会被保护，不会被后续大量请求挤掉。
- 插件禁用或卸载时，所有属性、注入的按钮与监听器都会被移除。

## 调试

插件在 `activate` 时挂一个调试出口 `window.__echoTree`（停用时摘掉）。宿主 DevTools 需先在「设置 → 实验性功能 → 开发者工具」打开才能按 F12；插件代码又跑在 Blob URL 里、行号映射不到源码，所以排查问题基本靠这个出口。

```js
__echoTree.help()            // 打印全部用法
__echoTree.containers()      // 当前接管的楼层与摘要
__echoTree.rows(el?)         // 回复的真实 DOM 顺序、层级与全部标记
__echoTree.tree(el?)         // 最近一次算出的回复树（父先子后）
__echoTree.recompute(el?)    // 立刻重算（不传=全部楼层）
__echoTree.settings()        // 当前生效的设置
__echoTree.guides(el?)       // 引导线绘制快照
__echoTree.css(el?)          // 关键计算样式
```

- 参数传元素表示那个楼层，传数字表示第 n 个，不传取第一个；返回的都是副本，控制台里翻看不会改坏内部状态。
- `guides()` 给出量出来的头像/底栏矩形、图层的 `viewBox` 与内联定位、每条分支的路径与节点坐标。**线没画出来时**先看 `anchors` 里是不是有 `null`（那条回复量不到头像），再看 `branches` 是否为空（算出来没有可连的子回复）。
- `css()` 给出容器与一条代表回复的关键计算样式，含红点伪元素 `::after`。用来确认注入的 CSS 有没有生效、缩进与分界线有没有被宿主覆盖。

## 二次开发

源码在 `src/`，交付物 `index.js` 是打包产物（宿主通过 Blob URL 加载入口，入口里的相对 `import` 不会被解析，所以必须自包含单文件）。

```bash
npm install                 # 只需一次，装 esbuild
node build.mjs              # 最大压缩，生成交付物 index.js
node build.mjs --test       # 压缩但保留函数名，便于对照堆栈
node build.mjs --out x.js   # 写到别的文件，不覆盖交付物
node build.mjs --watch      # 改 src/ 后自动重建
```

打包与压缩都用 **esbuild**（`build.mjs` 只负责把 CSS 转成字符串模块、校验 CSS 结构、加文件头）。自己写词法扫描容易在细节上出错——例如 `[data-x] .y` 被压成 `[data-x].y` 就永远匹配不上；交给 esbuild 后这类问题由工具保证。

`src/styles.css` 在构建期被压缩成字符串常量内联进 `index.js`，产物无任何 `.css` 引用，运行时零额外开销。默认模式重命名局部标识符；`--test` 模式保留函数名与标识符，线上崩溃时堆栈能直接对上 `src/` 的代码。

| 模块 | 职责 |
| --- | --- |
| `src/constants.js` | 常量、默认值、宿主选择器清单 |
| `src/i18n.js` | **全部面向用户的文案**（含「上一页 / 下一页 / 加载更多」），带占位符替换与语言回落 |
| `src/util.js` | 无副作用的小工具 |
| `src/tree.js` | 回复树构建、分页切分、缩进步长（纯函数） |
| `src/settings.js` | 设置规整与读取 |
| `src/meta-cache.js` | `/comment/*` 响应 → 「昵称 + 时间」→ pid 的关系缓存 |
| `src/runtime.js` | 共享的响应式设置状态 |
| `src/order.js` | 按树序重排回复节点，停用时按原始次序还原 |
| `src/dom.js` | 宿主 DOM 读取与痕迹清理 |
| `src/mark.js` | 红点坐标：量名字行最右侧的有效内容 |
| `src/guides.js` | SVG 引导线图层：分支路径、折叠节点、命中区 |
| `src/pager.js` | 楼层内分页条 |
| `src/interactions.js` | 点击意图解析 |
| `src/container.js` | 楼层容器的装配与重算 |
| `src/settings-page.js` | 设置页组件 |
| `src/styles.css` | 全部样式 |
| `src/entry.js` | 入口：activate / deactivate 编排 |

### 多语言化

界面上不存在硬编码文案：所有字符串都在 `src/i18n.js` 的 `MESSAGES` 里按 locale 分组，组件只写 `t("key")`，占位符写成 `{name}`。新增语言时只加一个 locale 分组，缺失的键自动回落到中文。测试会扫描 `src/` 下除 `i18n.js` 以外的所有文件，出现中文字面量即失败。

## 测试

```bash
node --test tests/threaded-comments.test.mjs tests/threaded-comments.dom.test.mjs tests/build.test.mjs
```

- `threaded-comments.test.mjs`：纯函数（设置归一化、树构建断环 / 深度上限 / 同级排序、对齐键、缩进步长）+ 文案与产物自包含。
- `threaded-comments.dom.test.mjs`：用最小 DOM 桩驱动完整链路 —— 拦截器采集关系 → 楼层打标 → 一级回复由根分支串联 → 子回复排到父评论下方 → 隐藏引用 → 折叠 → 分页切页 → 加载更多后保持折叠 → 关闭与卸载清理与顺序还原。
- `build.test.mjs`：对**打包产物**跑一次真实 `activate`，校验注入的 CSS 结构完整（花括号与 `!important` 数量对齐源文件、关键规则齐全、选择器里的后代组合子空格没被吃掉）、导出与拦截器契约不变、运行时字符串保留、`--test` 产物保留函数名且同样能激活。

## 兼容性

- 需要 EchoMusic `>=2.3.2`。
- 依赖宿主的评论楼层类名（`.comment-floor-inline`、`.comment-floor-reply` 等）。宿主若调整这些类名，插件会安静地不生效，不会破坏页面。

## 持续集成

`.github/workflows/build.yml` 在每次推送到 `main` 后重新打包、跑一遍 `npm test`，再把打出来的产物与仓库里的 `index.js` 逐字节比对（先打包再测试：测试读的是仓库里的 `index.js`，不先打包就会测到上一版产物）。两条都过就不管；产物对不上说明提交时忘了打包（或打包环境与提交的不一致），action 会用自己打出来的那份覆盖 `index.js` 提交回 `main`，提交信息带 `[skip ci]`，因此这次回写不会再触发一轮检查。

因此推送前不必强制先打包，但要让 CI 无事可做，还是本地 `node build.mjs && npm test` 一遍再提交。`index.js` 在 `.gitattributes` 里标了 `-text`：它是字节产物，换行被转换过就会让比对误报。

要让 action 能写回仓库，仓库设置里 `Settings → Actions → General → Workflow permissions` 需选 `Read and write permissions`；`main` 若有分支保护规则，需允许 `github-actions[bot]` 直推，否则回写那步会失败（测试与比对不受影响）。

## 已知限制

- 宿主楼层回复是「加载更多」式累加列表：楼内分页只在已经加载到本地的回复中切页，翻到末页后需要点「加载更多」才会追加新回复。
- 同楼层内出现「同昵称 + 同秒」的回复时，该组会被当作无法判别而不缩进。
- 引导线坐标在每次重算时按真实矩形现量一次，窗口尺寸变化或字体加载完会触发重算；宿主若在动画中改变高度，线段可能短暂滞后一帧。
- 开启「固定高度回复容器」时不画根分支：主评论在滚动区之外，而图层随内容滚动，线头会滚出视口。这与参考实现的处理一致。
